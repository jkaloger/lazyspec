## Changes

Goal: moment cycled enum value introduces dep on config section MISSING from buffer → insert section w/ parser-matching defaults → mark required-but-empty (sqids `salt`) → offer focus jump → SKIP when section already present. Save/validation UNCHANGED (slice-3 `Config::parse` config.rs:508 cross-field checks config.rs:540-592 reused, still reject empty salt → buffer can't save into invalid state).

Dependent sections = `Option<...>` fields on `DocumentConfig` in the in-memory buffer (config.rs:185-198): `sqids: Option<SqidsConfig>`, `reserved: Option<ReservedConfig>`, `github: Option<GithubConfig>`. "Insert section" = set the `Option` field to `Some(...)`; "section present" = field `is_some()`. Defaults match parser fns: `SqidsConfig{salt:String, min_length:u8}` (default_sqids_min_length=3 config.rs:50); `ReservedConfig{remote:String (default_reserved_remote="origin" config.rs:70), format:ReservedFormat, max_retries:u8 (default_reserved_max_retries=5 config.rs:74)}`, `ReservedFormat` Incremental/Sqids config.rs:54-59; `GithubConfig{repo:Option<String>, cache_ttl:u64}` (default_cache_ttl=60 config.rs:337, parser default repo=None).

### Task 1 — Pure scaffold fn: cycled-enum → mutated buffer (insert dep section w/ parser defaults, skip if present)
ACs: AC1 AC4 AC5 AC6.
Files: `src/tui/state/app.rs` (new pure fn + helper enum), or factor into `src/tui/state/forms.rs` if cleaner — keep it a free/assoc fn taking `&mut Config` so it's `App`-free + unit-testable.
- Add `pub fn scaffold_dependency(buffer: &mut Config, dep: ConfigDep) -> Option<ScaffoldResult>` — pure: given dirty buffer + the dep the just-cycled enum introduces, insert missing section w/ parser-matching defaults, return what was scaffolded (or `None` when skipped).
- `pub enum ConfigDep { NumberingSqids, NumberingReserved, Github }` — the three section deps enum cycling can introduce. Map FROM the cycled value: `numbering`→`sqids` ⇒ `NumberingSqids`; `numbering`→`reserved` ⇒ `NumberingReserved`; `store`→`github-issues` ⇒ `Github`. (`numbering`→`incremental`, `store`→`filesystem`/`git-ref` introduce NO dep → caller passes nothing / fn not invoked.)
- Body, per `dep`:
  - `NumberingSqids` (AC1): if `buffer.documents.sqids.is_some()` → return `None` (AC6 skip). Else `buffer.documents.sqids = Some(SqidsConfig{ salt: String::new(), min_length: 3 })` (matches default_sqids_min_length). Return `Some(ScaffoldResult)` flagging `salt` required-but-empty.
  - `NumberingReserved` (AC4): if `buffer.documents.reserved.is_some()` → `None` (AC6). Else `buffer.documents.reserved = Some(ReservedConfig{ remote: "origin".to_string(), format: ReservedFormat::Incremental, max_retries: 5 })` (remote/max_retries match default fns; format default = `incremental` per AC4). Return `Some(ScaffoldResult)` w/ NO required-but-empty field (all defaults valid).
  - `Github` (AC5): if `buffer.documents.github.is_some()` → `None` (AC6). Else `buffer.documents.github = Some(GithubConfig{ repo: None, cache_ttl: 60 })` (parser defaults: repo None config.rs:343, cache_ttl default_cache_ttl=60 config.rs:337). Return `Some(ScaffoldResult)` w/ no required-but-empty (`repo` is legitimately `Option`; `[github]` w/o repo parses — config.rs test_github_issues_without_repo_parses).
- `pub struct ScaffoldResult { pub inserted: ConfigDep, pub required_empty_field: Option<FieldPath> }` — `required_empty_field` = `FieldPath` (slice-3 vocabulary) pointing at first required-but-empty field, `Some` ONLY for `NumberingSqids` (the sqids `salt`), `None` otherwise. Drives AC2 flag + AC3 jump offer. If `FieldPath` (ITER-188) not yet landed, carry the section+key identifying the salt field in whatever shape slice-3 nav uses; describe seam, don't invent API.
Verify: deferred to Test Plan (pure fn unit tests on each `ConfigDep` + skip case).

### Task 2 — Hook scaffold into enum-cycle commit (`settings_space`), record pending required-but-empty + jump offer
ACs: AC1 AC2 AC3 AC4 AC5 AC6.
Files: `src/tui/state/app.rs` (extend slice-3 `settings_space` EnumCycle arm); settings state on `App` (slice-1 `SettingsState`, extend).

  - On `Some(result)`: store `self.settings.scaffold_offer = Some(result)` (new state, Task 3) so the screen can flag the required-but-empty field (AC2) + offer the jump (AC3). `dirty` already true from the enum write.

- Idempotence (AC6): re-cycling back to a dep value whose section already exists inserts nothing + leaves values untouched. Cycling AWAY then BACK: section persists in buffer (Option stays `Some`) → second arrival hits the `is_some()` skip. Do NOT clear the section on cycling away (out of scope; section removal is not this slice).
Verify: deferred to Test Plan (App-state on `settings_space` for cycle→scaffold + skip).

## Notes

- Build dep: **STORY-139 / ITERATION-188** (slice 3) — provides base enum-cycle editor (`EnumCycle{variants,idx}` + `settings_space`), the dirty `buffer: Config` on `SettingsState`, atomic `write_config_in_place` save, and whole-config validation via `Config::parse`. This slice ONLY adds the auto-insert side-effect on top of `settings_space`'s EnumCycle arm; save + validation are unchanged. Also transitively depends on **STORY-137 / ITERATION-186** (slice 1: `ViewMode::Settings`, nav model, settings render, `SettingsState`) and **STORY-138 / ITERATION-187** (slice 2: reload primitive that slice-3 save calls). All three siblings were TODO stubs when this was authored → tasks reference their seams (`SettingsState`, `buffer`, `settings_space`, `FieldPath`, nav model, focus-jump) by name; exact field/fn names follow those slices once landed.
- Dependent sections are the `Option<...>` fields on `DocumentConfig` in the in-memory buffer (config.rs:185-198), NOT raw TOML — scaffolding = setting `documents.sqids`/`reserved`/`github` to `Some(...)`; "present" = `is_some()`. Slice-3's `write_config_in_place` serializes those `Some` fields back into `[numbering.sqids]`/`[numbering.reserved]`/`[github]` tables at save time (ITER-188 Task 1 already handles these sections), so this slice writes nothing to disk.
- Defaults match the parser's default fns exactly so a scaffolded section is byte-identical to one the parser would have filled: sqids `min_length` = `default_sqids_min_length()` = 3 (config.rs:50); reserved `remote` = `default_reserved_remote()` = "origin" (config.rs:70), `max_retries` = `default_reserved_max_retries()` = 5 (config.rs:74), `format` = `incremental` (AC4); github `cache_ttl` = `default_cache_ttl()` = 60 (config.rs:337), `repo` = None (config.rs:343 — `Option`, `[github]` w/o repo parses).
- Key decision 1 — **scaffold logic is a pure fn** (`scaffold_dependency(&mut Config, ConfigDep) -> Option<ScaffoldResult>`), `App`-free, so AC1/AC4/AC5/AC6 are unit-tested on buffer state alone (given buffer + cycled enum → mutated buffer) without a terminal. `settings_space` is the only impure caller (records the offer + dirty).
- Key decision 2 — **only `NumberingSqids` carries a required-but-empty field** (sqids `salt`). `NumberingReserved` (all defaults valid) and `Github` (`repo` legitimately optional) scaffold complete-valid sections → no AC2 flag, no AC3 jump offer. So AC3's "offer jump" fires only for the sqids salt path.
- Key decision 3 — **guidance only, validation unchanged** (AC7): auto-scaffolding pre-creates the section + flags the empty salt but does NOT fill it or relax `Config::parse`'s `salt.is_empty()` check (config.rs:552-554). Buffer therefore cannot be saved into an invalid state — save still rejects the empty salt via the slice-3 path.
- Key decision 4 — **cycling away does NOT remove the scaffolded section** (Option stays `Some`); re-arriving at the dep value hits the `is_some()` skip (AC6). Section removal / cleanup is out of scope.
- OUT of this slice: base enum-cycle editor + atomic save + whole-config validation (slice 3, this only adds auto-insert on top); collection add/delete (slice 5); read-only view (slice 1); reload machinery (slice 2); removing a dependent section when its enum is cycled away.
