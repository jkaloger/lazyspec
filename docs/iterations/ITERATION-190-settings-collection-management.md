## Changes

Slice 5 of RFC-023. Layers `n` (seed default entry + drill in) and `d` (delete behind confirm) onto the 4 collection categories. Slice 1 (ITER-186) gives `ViewMode::Settings` + read-only entry-list render + drill nav (`settings_category`/`settings_entry`/`settings_drill` cursors). Slice 3 (ITER-188) gives the dirty `buffer: Config` on settings state + scalar field editors + atomic `toml_edit` save. THIS slice only mutates the in-memory dirty `buffer` (insert/remove entries); persistence is slice-3 save (NOT re-implemented). All mutations on `buffer`, never on session `&Config`.

Collection categories (per ITER-186 task 6): idx 1 Document Types → `buffer.documents.types: Vec<TypeDef>`; idx 2 Relationships → `buffer.relationships: Vec<RelationshipDef>`; idx 3 Validation Rules → `buffer.rules: Vec<ValidationRule>`; idx 7 Certification → `buffer.certification.overrides: HashMap<String,CertificationOverride>`. Seed shapes from `starter_types()` (config.rs:380), `default_rules()` parent-child (config.rs:437), `starter_relationships()` shape (config.rs:169 — single `RelationshipDef`), `CertificationOverride{normalize: default_normalize()}` (config.rs:313-320). NOTE: settings-state symbol names (`SettingsState`, `buffer`, `dirty`, `settings_*` cursors) follow slice 1/3 once landed; reference by name — both siblings were TODO stubs when authored.

## Notes

- Build deps: **STORY-139 / ITERATION-188** (slice 3) — provides the dirty `buffer: Config` on settings state + `dirty` flag + `editing` flag + scalar field editors + the atomic `toml_edit` `settings_save` (`write_config_in_place` + `Config::parse` re-validate) that PERSISTS this slice's buffer insert/remove mutations (AC8). **STORY-137 / ITERATION-186** (slice 1) — provides `ViewMode::Settings`, `settings_category`/`settings_entry`/`settings_drill` cursors, collection entry-list render + drill-in nav this slice's `n`/`d` hook into. Both siblings were TODO stubs when authored → settings-state symbol names (`SettingsState`, `buffer`, `dirty`, `editing`, cursor fields) follow them once landed; tasks describe the seam by name.
- **ADR-011 guard (AC6)**: a config with no `[[relationships]]` is a HARD load error — `Config::parse_inner` bails when the block is missing (config.rs:530-536), covered by `parse_without_relationships_block_is_hard_error` (config.rs:1194-1213). So the buffer must never produce a relationships-less config: refuse deleting the last `[[relationships]]` entry. Guard lives in the OPEN path (`settings_open_delete_confirm`) → refusal means NO confirm overlay shown (matches AC6), not a confirm-then-block. The 3 other collections (types, rules, overrides) have no such floor (rules/overrides may be empty; `[[types]]` non-empty is enforced at SAVE by `Config::parse` config.rs:523-528, not by a per-entry delete guard this slice — out of scope, save catches it).
- Key decision — **buffer-only mutations**: `n`/`d` operate solely on the in-memory dirty `buffer: Config`, never the session `&Config` and never the disk file. Disk write is exclusively slice-3 `settings_save`. So a new confirm-state struct (`SettingsDeleteConfirm` targeting a buffer collection Index/Key) is needed rather than reusing `DeleteConfirm` (forms.rs:89-94), which targets a doc file `PathBuf` + doc refs + invokes `cli::delete::run_with_config` (app.rs:1200) — irrelevant to buffer entries.
- Key decision — **overrides key prompt**: `[certification.overrides]` is a keyed map (`HashMap<String,CertificationOverride>` config.rs:301), so `n` can't seed a positional entry like the 3 `Vec` collections — it must prompt for the spec-path key first (`OverrideKeyPrompt` overlay), then insert `{normalize: default_normalize()}` (config.rs:313-320) keyed by the trimmed path. Entry list iterates overrides in sorted-key order (ITER-186 task 6 note) for deterministic render/tests; `settings_entry` after insert = the new key's sorted index.
- Seed shapes: types from `starter_types()` simple closure (config.rs:381-393) — incremental/filesystem/empty-agents placeholder; rule from `default_rules()` parent-child variant (config.rs:439-445); relationship a single symmetric `RelationshipDef{name, inverse:None}` (config.rs:159-163, mirrors `related-to` config.rs:178-181). Seeded fields are placeholders the user fills via slice-3 scalar editors (drill-in is immediate per AC1/AC2/AC3); save-time `Config::parse` validation (slice 3) catches an unfilled invalid entry.
- Scope OUT (downstream/sibling): scalar field editing within a drilled entry (slice 3, ITER-188); read-only drill-in nav + breadcrumb (slice 1, ITER-186); dependency auto-scaffolding on add (slice 4, ITER-189); atomic save + load-validation machinery (slice 3); doc-impact guard on `dir`/`prefix`/`store` change (slice 6). This slice adds ONLY `n`-seed-and-drill + `d`-delete-behind-confirm + the ADR-011 last-relationship guard.
