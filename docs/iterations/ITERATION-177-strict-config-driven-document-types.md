## Context

The engine still bakes the RFC/Story/Iteration/ADR ontology into code through three opinionated seams in `src/engine/config.rs`, even though `DocType` is already an open `DocType(String)` newtype (`src/engine/document.rs:54`) that accepts any string. Those seams are: the built-in type fallback (`default_types()`, lines 351-383, plus the `build_type_def` pluralization helper at 332-348), the named-field `Directories` struct (lines 244-250) that structurally assumes `rfcs`/`adrs`/`stories`/`iterations` exist together with the `directories_from_types`/`types_from_directories` helpers (410-433), and the lenient `Config::parse`/`Config::load` path (484-590) that silently falls back to those defaults when `[[types]]` or the whole file is absent. This slice removes that built-in vocabulary so declared `[[types]]` in `.lazyspec.toml` is the sole source of truth, deriving directories from each type's own `dir`/`plural` fields. Runtime directory resolution already reads `type_def.dir` (`src/engine/store.rs:59`, `src/cli/create.rs:127`, `src/engine/store_dispatch.rs:76`) and never reads `filesystem.directories`, so `Directories` is dead at resolution time -- this is mostly deletion and load-path error wiring, not a model change.

## Test Plan

All new load-path tests live in `tests/integration/config_test.rs` and drive the public `Config::parse` / `Config::load` APIs (structure-insensitive, behavioral). End-to-end ACs use the compiled binary via `env!("CARGO_BIN_EXE_lazyspec")` (the pattern already used in `tests/integration/reservation_test.rs:335`) against a fresh `TempDir` (isolated, deterministic). The `FileSystem` trait seam (`Config::load(root, &dyn FileSystem)`) is used where we want to exercise load without spawning a process.

- **AC1 (no `.lazyspec.toml` -> error pointing at `init`).** Test `load_without_config_file_errors_pointing_to_init` in `config_test.rs`. Arrange: a `TempDir` with no `.lazyspec.toml`, plus a `RealFileSystem`. Act: call `Config::load(tmp.path(), &fs)`. Assert: `is_err()` and the message contains `init` and `.lazyspec.toml`. Complement with one end-to-end test `cli_create_without_config_errors` (in `cli_create_test.rs` or a small new `cli_no_config_test.rs`) that runs the binary `create rfc "X" --json` in an empty `TempDir` and asserts non-zero exit plus an `init` hint on stderr -- this proves the error reaches the CLI surface, not just the engine. Tradeoff: asserting on substring (`init`) rather than exact wording keeps the test resilient to copy edits while still pinning the contract.

- **AC2 (file exists but no `[[types]]` -> hard error naming missing `[[types]]`).** Test `parse_without_types_errors` in `config_test.rs`. Arrange: a TOML string with `[naming]`/`[templates]` but no `[[types]]` and no `[directories]`. Act: `Config::parse(toml)`. Assert: `is_err()` and the message contains `types` (and the `init` remedy). This replaces the existing `no_types_or_directories_uses_defaults` test, whose premise (silent default set) is exactly what we are deleting.

- **AC3 (arbitrary type set with no rfc/story/iteration/adr succeeds for create/list/validate).** End-to-end test `arbitrary_types_create_list_validate` in a new `tests/integration/cli_no_config_test.rs` (or appended to `config_test.rs` for the parse half plus a binary run for the e2e half). Arrange: a `TempDir` whose `.lazyspec.toml` declares only `ticket` (dir `docs/tickets`, plural `tickets`, prefix `TICKET`) and `epic` (dir `docs/epics`, plural `epics`, prefix `EPIC`), no validation rules referencing built-in types, and a templates dir with `ticket.md`/`epic.md`. Act: run the binary `create ticket "First" --json`, then `list --json`, then `validate --json`. Assert: create exits 0 and writes under `docs/tickets/`; list includes the ticket; validate exits 0 with no error mentioning unknown/missing built-in types. This proves the engine assumes no specific type names.

- **AC4 (directories derive entirely from declared types' `dir`/`plural`, not named config fields).** Test `directories_derive_from_declared_type_dirs` in `config_test.rs`. Arrange: a TOML declaring two types with non-default `dir` values (e.g. `rfc` -> `specs/rfcs`, `epic` -> `planning/epics`). Act: `Config::parse(toml)`. Assert: `config.type_by_name("rfc").unwrap().dir == "specs/rfcs"` and `config.type_by_name("epic").unwrap().dir == "planning/epics"`, and -- to prove the named struct is gone -- that there is no longer any `config.filesystem.directories.rfcs`-style access compiling (covered structurally by deleting the field; assert via the type-driven path only). Pair with a `Store::load`-through-`FileSystem` assertion that a doc placed under the declared `dir` is discovered, confirming resolution flows through `type_def.dir`.

- **AC5 (omitting a previously-built-in type, e.g. `spec`, leaves it absent and never injected).** Test `omitted_builtin_type_is_absent` in `config_test.rs`. Arrange: a TOML declaring `rfc` and `story` only (no `spec`). Act: `Config::parse(toml)`. Assert: `config.type_by_name("spec").is_none()` and `config.documents.types.len() == 2`. This replaces `default_config_has_four_type_defs` / `default_config_has_convention_and_dictum_types`, which assert injection.

- **AC6 (explicit `plural` taken verbatim, no engine-side `story`->`stories` special-casing).** Test `explicit_plural_taken_verbatim` in `config_test.rs`. Arrange: a TOML with a `story` type whose `plural` is `stories`, and a second type `story`-shaped with a deliberately odd plural (e.g. type `quux` with `plural = "quuxen"`) to prove no transformation occurs. Act: `Config::parse(toml)`. Assert: `type_by_name("story").unwrap().plural == "stories"` and `type_by_name("quux").unwrap().plural == "quuxen"`. Because `plural` is a required `TypeDef` field with no default, a missing `plural` already errors at parse; add `missing_plural_field_errors` asserting `Config::parse` fails mentioning `plural` to lock in that the helper is gone and the field is mandatory.

Test-property note: existing tests in `config_test.rs` and several engine/cli unit modules construct `Config::default()` as a fixture (~101 call sites). The plan keeps a test-only default fixture (see Changes task 5) so those fixtures keep compiling; only the production load path becomes strict. Tests that assert the *content* of the old defaults (`default_config`, `default_config_has_four_type_defs`, `default_config_has_convention_and_dictum_types`, `default_config_has_three_default_rules`, `no_types_or_directories_uses_defaults`, `legacy_directories_populates_types`, `parse_config_from_toml`'s `[directories]` block, `no_rules_section_uses_defaults`) are updated or removed because they encode the behavior being deleted.

## Changes

1. **Delete the named-field `Directories` struct and its derivation helpers (AC4).** File: `src/engine/config.rs`. Delete the `Directories` struct (lines 244-250), the `directories: Directories` field on `FilesystemConfig` (line 167), the `directories: Option<Directories>` field on `RawConfig` (line 318), the `directories_from_types` helper (410-424), and the `types_from_directories` helper (426-433). `FilesystemConfig` keeps only `templates: Templates`. In `Config::parse`, delete the `types_from_directories(dirs)` branch and the entire `let directories = ...` block (484-496), and remove `directories,` from the returned `FilesystemConfig` literal (567). Because `Templates` is the only remaining `FilesystemConfig` field, keep `#[serde(flatten)]` on `filesystem` so `[templates]` stays top-level in TOML. Verify: `cargo build` -- expect compile errors at the three test fixtures listed in task 4 and the `config_test.rs` cases asserting `filesystem.directories`; those are fixed in tasks 4-6.

2. **Make `Config::parse` a hard error when `[[types]]` is absent (AC2).** File: `src/engine/config.rs`, in `Config::parse` (~484). Replace the `let types = if let Some(types) = raw.types { ... } else { default_types() }` chain with: if `raw.types` is `None` or an empty `Vec`, `bail!` an error that names the missing `[[types]]` and points at `init` (e.g. `".lazyspec.toml is missing required [[types]]. Run `lazyspec init` to scaffold a config."`). Otherwise bind the declared types. Keep all existing per-type numbering/store validation after this point unchanged. Verify: `cargo test --test main config_test::parse_without_types_errors` (after task 6 adds it) passes; `cargo build` clean.

3. **Make `Config::load` a hard error when `.lazyspec.toml` is absent (AC1).** File: `src/engine/config.rs`, `Config::load` (~580). Replace the `Ok(Self::default())` fallback (589) with a `bail!` when `fs.exists(&path)` is false, message naming the missing `.lazyspec.toml` and instructing the user to run `lazyspec init` (the strict-load remedy from ADR-011). Keep the existing read+parse branch when the file exists. Note: `init` itself does not call `Config::load` (it builds `Config::default()` directly in `src/cli/init.rs:14`), and `completions` already tolerates a load failure (`src/cli/completions.rs:21` matches on the `Result`), so this change does not break `init`/`completions`. Verify: `cargo test --test main config_test::load_without_config_file_errors_pointing_to_init` passes; manually `cargo run --quiet -- create rfc "X"` in an empty temp dir prints the init hint and exits non-zero.

4. **Remove the engine-side pluralization helper and the built-in default type set (AC5, AC6).** File: `src/engine/config.rs`. Delete `default_types()` (351-383) and `build_type_def` (332-348, the `"story" => "stories"` special-case lives here). Delete `default_rules()` (385-408) only if it is no longer referenced after task 5; otherwise leave rule defaults for STORY-126/127 and just confirm `default_rules` no longer feeds the load path (it is currently consumed via `raw.rules.unwrap_or_else(default_rules)` at 498 -- change that to `raw.rules.unwrap_or_default()` so missing `[[rules]]` yields an empty `Vec`, not a built-in rule set, consistent with "engine carries no rules"). Verify: `cargo build`; grep confirms no remaining references to `build_type_def` or `default_types`.

5. **Rework `impl Default for Config` into a test-only fixture, not a production fallback (AC1, AC2; supports ~101 test sites).** File: `src/engine/config.rs`. After tasks 1-4, `impl Default for Config` (435-462) currently calls the now-deleted `default_types`/`directories_from_types`/`default_rules`. Production no longer needs `Default` (the only production caller was `Config::load`'s fallback, removed in task 3; `init` builds its starter config -- see task 7). To avoid a 101-site churn that belongs to no AC, gate the default constructor behind `#[cfg(test)]` and inline a self-contained starter type set (rfc/story/iteration/adr/spec/convention/dictum with explicit `plural` values, no helper) plus empty/standard rules, so `Config::default()` remains available to tests only. Update its body to drop the `directories` field. Verify: `cargo build` (non-test) clean with no `Default` for `Config` in the non-test build; `cargo test` compiles all fixtures.

6. **Update `init` to construct its starter config without `Config::default()` (AC1 remedy correctness).** File: `src/cli/init.rs:14`. Since `Config::default()` is now `#[cfg(test)]`, replace `let config = Config::default();` with an explicit starter `Config` built in `init` (the canonical rfc/story/iteration/adr/spec/convention/dictum types with their `dir`/`plural`/`prefix`/`icon`, the standard rules, default naming and templates dir). This is the "sole home for defaults is the config `init` writes" from ADR-011. Keep `to_toml()` writing `[[types]]` (and `[templates]`, `[naming]`) -- confirm the emitted TOML no longer contains a `[directories]` table (it will not, since the struct is deleted). Verify: `cargo run --quiet -- init` in a fresh temp dir produces a `.lazyspec.toml` with `[[types]]` and no `[directories]`, and a follow-up `create rfc "X"` succeeds; `cargo test cli_init_test` passes.

7. **Update existing tests that encode the deleted defaults (all ACs; keeps the suite green).** Files: `tests/integration/config_test.rs`, `tests/integration/common/mod.rs`, `src/engine/config.rs` (the `#[cfg(test)] mod tests`), and the three in-tree fixtures that build `Directories` literally: `src/cli/lease.rs:363`, `src/engine/git_ref_store.rs:372`, `src/engine/store_dispatch.rs:1689`. In each of the three fixtures, delete the `directories: Directories { ... }` line from the `FilesystemConfig` literal and drop the now-unused `Directories` import. In `config_test.rs`: delete `parse_config_from_toml` (`[directories]` premise), `default_config`, `default_config_has_four_type_defs`, `legacy_directories_populates_types`, `no_types_or_directories_uses_defaults`, `no_rules_section_uses_defaults`, `default_config_has_three_default_rules`, and `default_config_has_convention_and_dictum_types`, or rewrite them to the new strict contract. In `common/mod.rs`, `TestFixture::config()` returns `Config::default()`; keep it (now backed by the `#[cfg(test)]` fixture) so the 100+ CLI/TUI fixtures keep working. Verify: `cargo test` -- full suite green; specifically `cargo test --test main` and `cargo test --lib`.

8. **Add the new AC tests (AC1-AC6).** Files: append load-path tests to `tests/integration/config_test.rs` (`load_without_config_file_errors_pointing_to_init`, `parse_without_types_errors`, `directories_derive_from_declared_type_dirs`, `omitted_builtin_type_is_absent`, `explicit_plural_taken_verbatim`, `missing_plural_field_errors`) and add a new `tests/integration/cli_no_config_test.rs` for the end-to-end binary cases (`cli_create_without_config_errors`, `arbitrary_types_create_list_validate`). Register the new file in `tests/integration/main.rs` (the integration harness aggregates modules there). Use `TempDir` + `RealFileSystem` for engine-level tests and `env!("CARGO_BIN_EXE_lazyspec")` for binary tests, mirroring `reservation_test.rs`. Verify: `cargo test` runs and all eight new tests pass; `cargo run --quiet -- validate --json` on this repo still works.

Sequencing rationale: task 1 (delete `Directories`) and task 4 (delete the default type set + pluralizer) remove the structures; tasks 2-3 wire the strict-load errors that replace the deleted fallbacks; task 5 retains a test-only `Default`; tasks 6-7 fix the production starter (`init`) and the fixtures/tests broken by the deletions; task 8 adds the verifying tests last so the suite is green throughout.

## Notes

- Real file paths confirmed: `src/engine/config.rs` (all type/`Directories`/load logic), `src/engine/document.rs:54` (`DocType(String)` newtype), `src/engine/store.rs:59` and `src/cli/create.rs:127` and `src/engine/store_dispatch.rs:76` (runtime dir resolution via `type_def.dir`), `src/cli/init.rs:14` (only production `Config::default()` caller), `src/main.rs:64` (single `Config::load` entry point), `src/cli/completions.rs:21` (load-failure-tolerant caller). `Directories` literals to fix in fixtures: `src/cli/lease.rs:363`, `src/engine/git_ref_store.rs:372`, `src/engine/store_dispatch.rs:1689`.
- Key discovery: `filesystem.directories` is never read for document placement at runtime -- `Store::load` iterates `config.documents.types` and uses `type_def.dir`. The `Directories` struct is purely a serde round-trip artifact, so deleting it is structurally safe (AC4 is already satisfied by the type-driven path; the work is removing the dead struct and its `[directories]` legacy parse branch).
- Key discovery: `build_type_def` (`config.rs:332`) is the sole home of the `"story" => "stories"` special-case; it is only invoked from `default_types` and `types_from_directories`, both deleted here, so AC6 is satisfied by deletion plus the existing required-`plural`-field behavior (no `#[serde(default)]` on `TypeDef::plural`, so a missing `plural` already errors).
- Scope guard: `Config::default()` has ~101 call sites, almost all test fixtures. Deleting it outright would be churn unrelated to any AC and would touch STORY-126-adjacent code. The plan instead makes the *load/parse path* strict (the actual production behavior ADR-011 governs) and retains a `#[cfg(test)]` `Default` fixture. The single production `Default` caller (`init`) gets an explicit starter config.
- Residual (intentionally out of scope): `DocType` associated consts `RFC/STORY/ITERATION/ADR/SPEC` (`document.rs:57-61`) are still referenced in `src/cli/status.rs:42-45` (default status-board ordering), `src/tui/state/forms.rs:55` (default form selection), and `src/engine/validation.rs:584,677` (spec-specific certification checks). These are string conveniences that do not gate document creation, listing, or directory resolution, so all six ACs hold with them present. Removing them belongs to spec-validation / status-display work, not this taxonomy slice. Noted so the reviewer knows the residual opinionation is deliberate.
- `default_rules()` / `[[rules]]` defaults straddle this story and STORY-126/127. This slice only ensures the *load path* injects no rules (missing `[[rules]]` -> empty `Vec`); the canonical rule set moves into `init`'s starter config alongside `[[types]]`. The richer `[[relationships]]` registry and rule-by-name wiring remain STORY-126/127.
